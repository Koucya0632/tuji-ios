# 複習提示把該題降級為一次答錯的評分

複習加了「點圖翻面看釋義」的求救提示（求救提示 / hint flip）。看過提示的題目一律套用
答錯的評分表 `[重來, 困難]`，建議值仍由對錯決定（答對→困難、答錯→重來）；自動評級因此
自然關閉，因為 `pick()` 的自動路徑要求建議值不是「困難」。

## Considered Options

**當作答錯（強制重來＋當場重排）** — 被拒。懲罰重到一定程度時使用者不會按這顆鍵，
會改成亂猜，而**亂猜猜對寫進 SRS 的「穩定」比誠實求救更髒**。這顆鍵必須輕到值得按，
不然它等於沒做，還白白多了一條評分分支。

**完全不罰（只靠既有的秒數機制）** — 被拒。翻面看字要花時間，超過 7 秒本來就會降到
困難，但手快的人 3 秒內翻完並答對仍會拿到「熟練」。提示變免費，求救鍵就成了跳過鍵。

## Consequences

重排進隊伍的條件**刻意沒有跟著改**，仍然是「有沒有選錯選項」。語意上「評了重來就該再
考一次」更一致，但那個改法會連帶改變既有行為（答錯選困難從此不再重排），屬於超出本功能
範圍的評分變更。結果是：看了提示、答對、又誠實選重來的字，SRS 會把它排到很近的未來，
但本輪不會再出現。

「這題用了提示」寫進 `study_logs.metadata`（以及自製圖鑑的 `atlas_study_logs`），不是
新增一個 `activity` 值——`activity` 命名的是題型，提示是題型上的修飾語，而且 `activity`
兩端都有封閉列舉與 DB CHECK 約束。`study_logs` 是 append-only，沒記下來就補不回來，
所以這個欄位在功能上線的第一天就要在。
