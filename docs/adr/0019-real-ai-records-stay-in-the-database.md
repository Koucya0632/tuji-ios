# 真實的 AI 紀錄只在什麼條件下離開資料庫

我們會讀使用者的 AI 紀錄（抽讀），唯一的目的是修 prompt。讀的時候看不到是誰；開發者自己的
帳號在查詢條件裡排除。讀到的東西離開資料庫的界線依功能而定：

- **主題對話的原文**永遠不進 repo、PR 或 issue，只能改寫成保留錯誤形狀的合成案例。
- **查詞與語法的輸入**（一個詞、一個句型）在 tuji-web 轉為 private 之後，可以原樣當測試案例；
  轉成 private 之前比照主題對話。
- **抽讀的完整輸出**永遠寫在 repo 外面。
- **缺詞統計**只列出至少 3 個不同的人查過的詞，只顯示詞與人數。
- AI 的好答案要進官方內容（記憶小撇步、詞庫、語法解說），一律先由人改寫。

**為什麼依功能區分**：主題對話的內容就是使用者的生活。Moira 問的是住哪裡、計畫、經驗，
所以去掉 user_id 也不等於匿名。查詞和語法的輸入幾乎只是語言本身，而且錯誤常常要原樣才能
重現。查詞的輸入是自由文字，只有一個人查過的詞最可能是人名、公司名或私人訊息；3 個人以上
都查過的詞幾乎一定是公共的語言知識，剛好就是圖鑑該補的。

## Considered Options

**全部改寫，查詞也不例外**：被拒。改寫查詞輸入常會讓錯誤消失，例如特定的錯字或混用語言的
寫法，而這類輸入本身幾乎不帶個人資訊。

**repo 轉成 private 之後全部可以用**：被拒。git 歷史會跟著 repo 走，以後再公開、交給外包或
加入協作者時，這些內容會一起過去；而主題對話是三種裡最私人的。

**跨使用者重用答案、或讓 Moira 記得以前的對話**：不在這個決定的範圍內。前者會碰到
ADR-0016 的點數模型；後者是需要另外設計的新功能，而且跨對話送出內容已超出隱私權政策 §4.2
「earlier messages in the same chat」的範圍。

## Consequences

情境故事在伺服器上不存，所以沒有東西可以抽讀；它的品質靠樣本檢查。隱私權政策 §1.4 雖然
列了 stories，但決定不改。
