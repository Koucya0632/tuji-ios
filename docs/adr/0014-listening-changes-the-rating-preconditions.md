# 聽句不自動評級，而且碼表從音檔播完才起算

**聽句**是複習的第二個題型：題目是那個字的例句**模糊**加上它的音檔，答案是兩張圖片二選一
（詞彙與其餘規則見 `CONTEXT.md`）。它改變了兩件複習評分一直依賴的前提，所以這裡把改動與
被拒的替代方案一起記下來。

**一、聽句一律出揭示表，不走自動評級。** `pick()` 的自動路徑在註解裡寫明了它的前提是
「建議值毫無疑義」（the suggestion is unambiguous）。二選一的猜對率是 50%：擲一次硬幣、
猜中、兩秒內按下去，在 MCQ 那條路上會自動套用 `computeSuggestion` 給的「熟練」並直接寫進
SRS，而使用者連評分畫面都沒看到。一次五五開的正確不是毫無疑義——它正好是同一個 `pick()`
裡另一個分支說的「使用者自己的判斷帶有訊號」。

**二、碼表從音檔播完才起算，但重播不歸零。** `advance()` 每題設 `startedAt = .now`，而
`computeSuggestion` 的 3 秒 / 7 秒門檻是為「圖片出現 → 作答」校準的。音檔會往那個碼表裡
混進三樣跟提取速度無關的東西：第一次播放的下載延遲、句子本身的長度（聽完前答不了，而
A2/B1 兩階不同長，en 平均 60 字元、ja 平均 25 字元也不同）、以及重播。不扣掉的話每一次
聽句作答都會超過 7 秒，**建議值永遠是困難**——把使用者往下拉間隔的方向推，對象是他聽得懂
的字。扣掉前兩樣之後，剩下的重播時間指向的方向是對的：聽三遍才答得出來的字，建議困難是
正確的，不是被污染。

**三、提示在這裡只花得起一半的錢。** 眼睛圖案解模糊走的是同一個 `hinted` 與同一份答錯評分表
`[重來, 困難]`（[ADR-0007](0007-review-hint-costs-a-downgrade.md)），理由是解模糊之後這題
已經不是聽力題而是「讀句子選圖」，句子裡就印著那個字。但 ADR-0007 的提示花的是**兩樣**
東西——評分表，加上關掉自動評級——而第二樣在聽句裡因為第一條決定本來就是關的。

## Considered Options

**四張圖片（2×2）** — 被拒。它是「其他什麼都不用改」的那條路：自動評級、`DistractorPool`、
評分表全部維持原狀，而版面也放得下（固定開銷 419pt，英雄圖 200–360pt，模糊例句只吃 60–80pt）。
放棄它是題型形狀上的選擇——二選一是這個題型指定的手感——**而放棄它的代價就是本文其餘每一條**。
記在這裡是為了讓下一個覺得「聽句怎麼這麼多特例」的人知道，那些特例都是同一個選擇的帳單。

**維持二選一、評分照舊** — 被拒。ADR-0007 拒絕「提示直接算答錯」時給的理由是**亂猜猜對寫進
SRS 的「穩定」比誠實求救更髒**。二選一把那個髒污率從 25% 抬到 50%，而且抬在唯一一條沒有人工
確認的路徑上。

**維持二選一、把可用評分上限壓到「穩定」** — 被拒。它只把自動寫入的**值**調小，沒有把自動
寫入本身拿掉。

**聽句用另一組秒數門檻，把音檔長度算進去**（`word_media.duration_ms` 是有的） — 被拒。
**重播讓任何以經過時間為基礎的量測都不成立**：聽三遍的人 `elapsed` 裡就有三段音檔，門檻再
怎麼補償都對不上。

**建議值完全不看秒數**（答對→穩定、答對但用過提示→困難、答錯→重來） — 被拒。它誠實而且
最省事，但它放棄速度訊號，聽句從此不會建議「熟練」。改成從音檔播完起算，等於把速度訊號買
回來。

**從最後一次播完起算** — 被拒。重播變成把碼表歸零，等於獎勵猶豫。

## Consequences

**每一道聽句題多一次點擊。** 這是二選一換來的，不是額外的。

**`study_logs.metadata.hinted` 跨題型比較不是同一把尺**（MCQ 花兩樣、聽句花一樣）。任何拿
`hinted` 做跨 `activity` 分析的人都會被騙，所以這件事也寫在讀取端的註解裡。

**`SpeechService` 必須發布播放狀態**，才有「播完了」這個事件。作法是 `@Observable`，不是為
這一個呼叫者加一個 `onFinish` 閉包——後者正是這個 repo 最常見的缺陷形狀（為一個呼叫者做的
東西，下一個找不到）。擋路的**不是** `NSObject`（那沒問題），是 `lazy`：`@Observable` 把每
一個儲存屬性改寫成計算屬性，而 `lazy` 不能用在計算屬性上。`SpeechService` 有兩個
（`synth:41`、`cacheDir:55`），各補一個 `@ObservationIgnored` 就過——已用 iOS 18 模擬器
target ＋ `-swift-version 6` 實際編譯驗證。它順手補掉 `PronunciationButton` header 裡記著的洞：「規格要求播放時
底色轉瞳黃。沒做：`SpeechService` 不是 `@Observable`，不發布播放狀態……它需要那個服務自己
講出來」。兩條播放路徑（clip 與合成）的收尾 delegate 本來就都實作了。

**播放失敗、或超過 3 秒還沒開始播，碼表直接起算並標 `audioFailed`。** 否則 `startedAt` 永遠
不會啟動。那一題的建議值不該被當成聽力表現。重播次數同樣記進 `metadata`，理由和 `hinted`
一樣：`study_logs` 是 append-only，沒記下來就補不回來，而 `metadata` 沒有約束、不需要
migration。

**離線或音檔未快取時，那張卡讓位給 MCQ。** `SpeechService.play` 抓不到 clip 就退回
`AVSpeechSynthesizer`，而日文漢字讀音由 iOS 猜、無處可改——那是預生成句子音檔的唯一理由。
它還特別難抓：它不是「失敗」，它會**成功地**唸出可能是錯的東西，所以 `audioFailed` 碰不到
它。連帶的結果是**題型在卡片成為 `current` 的當下才決定**，不是場次開始時一次分配完，因為
網路會在場次中途斷。學新字與詳情頁的離線合成不用跟著改：那兩處句子攤在眼前、聲音是配菜，
唸錯是瑕疵；這裡句子是遮住的、聲音就是題目。
