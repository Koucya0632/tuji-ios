# 自製圖鑑的 AI 只走罐頭點數

自製圖鑑的三段 AI——識別、確認、補充——只有一條路徑：罐頭點數的識別操作（`/api/ai`，
`lib/ai-operations`）。點數制之前的那條路徑（`/api/atlas` 下的上傳即識別、重新識別、確認、
補充，以及卡片詳情 GET 的 lazy 補充）整條退役，三端一起：

- **伺服器**：四個寫入端點固定拒絕（`refuseLegacyAtlasWrite`），詳情 GET 只讀不寫。
- **iOS / Android**：拍照新增只有 `CreditCaptureView` 一個流程；相機鍵先問 `CaptureEntry`，
  非會員直接看到會員頁。生成佇列只剩一種 job。

**為什麼現在刪**：舊路徑只有「有 Pro、沒有永久會員資格」的帳號走得到。2026-10-11 查正式庫，
這種帳號 0 個，30 天內舊路徑識別 0 次；Pro 已於 2026-10-06 停售。沒有人在用的那條路徑，卻讓
九條規則各有兩份 implementation，其中六條行為已經不同——重新確認會不會清掉舊釋義、補充只
成功一部分算不算完成、容量算不算進行中的、缺中文名的候選能不能交付。同一天修「改名後中文
名不更新」時，同一條規則改了兩處。

## Considered Options

**留著舊路徑，把兩邊共用的規則抽出來** — 被拒。抽共用 module 是在替一個沒有使用者的呼叫端
付維護成本，而且兩條路徑的交易模型不同（一邊是逐句寫入，一邊是帳務交易裡的單一 commit），
共用的部分比看起來少。deletion test 的答案很乾脆：刪掉之後複雜度是消失，不是搬家。

**舊端點直接 404** — 被拒。已上架的版本還會打這些端點。固定回它們本來就會處理的兩種答案
（罐頭點數帳號 409 `update_required`、其他帳號 402），舊版 App 看到的是「請更新」或會員頁，
而不是一個解析失敗。

## Consequences

**回滾的退路少一條。** `MEMBERSHIP_POLICY=v1` 與 `AI_CREDITS_MODE=off` 原本是「回到點數制
之前」的開關。現在回到那個狀態就沒有任何拍照新增路徑；要回滾只能 revert 這次的 commit。

**營運手動贈送的 Pro 不再帶 AI 拍照。** 贈與（ADR-0004）給的是 Pro tier，而 AI 現在跟著永久
會員資格走。要補償一個人的拍照額度，要贈點數，不是贈 Pro。

**補充只在確認時跑一次，沒有任何讀取會觸發它。** 這取代了 ADR-0011 裡兩件事：

- 「詳情 GET 保留付費副作用」——GET 現在只是讀取。當時不改是因為要動 iOS 合約；罐頭點數帳號
  的 GET 早已跳過補充，所以這次沒有合約要改。
- 「升級 `ATLAS_ENRICH_VERSION` 會讓 `skipped` 復活並重新補充」——版本現在只是戳記。配方
  改了、想讓既有卡片跟上，要另寫 backfill，並決定這筆錢誰出；不會因為有人點開詳情就發生。

ADR-0011 的核心仍然成立而且更簡單：每張卡的補充花費有一個有限上限，數字只有一個
（`ATLAS_ENRICH_MAX_ATTEMPTS`），用完就是 `skipped`。

**iOS 的範例 view model 換人。** `AtlasCaptureVM` 是 CONTEXT.md 點名的範例，它跟著舊流程
一起刪了；現在的範例是 `CreditCaptureModel`。
